# 运行工作流

[English](workflows.md) | 中文

已保存的工作流会在后台执行多 agent（智能体）任务，你可以同时继续使用 Chat。本指南假定 Web UI 已在运行，且你已在拥有该工作流的工作区中打开一个会话。

## 创建工作流

在 Chat 中输入 `/create-workflow`，并描述要自动执行的任务。创作轮次会引导模型编写、冒烟测试并保存定义。

在 Windows 上，随附的本地文件系统 provider 无法执行必需的不跟随链接读写。已保存定义的发现与保存（包括 `/create-workflow`）以及 workflow `script_path` 启动会以 `FS_IO_ERROR` 失败；请为这些操作配置其他文件系统 provider。内联脚本启动仍可用。

## 启动已保存的工作流

按名称启动已保存的定义：

```
/workflow release-audit
```

每个已保存定义还会获得启动别名。名称未被占用时，别名是以下更短形式：

```
/release-audit
```

名称与其他命令冲突时，该命令保留裸名，已保存工作流改用 `/workflow-release-audit`；如果该名称仍被占用，斜杠菜单会再添加一个 `workflow-` 前缀。定义或命令变化后，别名会同步更新。每种形式都会在后台启动运行并返回其显示名称。启动还会在 Chat 中打开一条持久工作流记录，跟踪成员状态并在刷新后保留；日志、结果、产物和控制则使用仪表盘。`/workflow <name>` 始终可用；它还接受位于名称之后的一个可选 JSON 对象。

## 监控运行

输入 `/workflows` 可打开当前会话的仪表盘。`/workflows` 是浏览器 action，因此打开它不会提交 Host 命令，也不会在 Chat 中添加 Host 命令行。

- **运行**会列出活跃运行和保留的历史运行，以及它们的状态、阶段、agent 预算和已用时间。
- **Agent** 会列出工作流成员。选择成员可检查其对脚本可见的结果，或在可用时打开子会话。
- 检查器提供 **Agent 结果**、**日志**、**运行结果**和**产物**视图。产物内容会根据需要从运行的 scratch 文件中加载。

## 控制运行

仪表盘只会显示当前对所选运行有效的操作。当焦点不在文本字段中时，可以使用按钮或不带修饰键的快捷键：

| 操作 | 快捷键 | 效果 |
|---|---|---|
| **暂停** | `P` | 清理后停止当前尝试，并保留逻辑运行以便恢复。 |
| **恢复** | `R` | 继续暂停或等待输入的运行。 |
| **停止** | `X` | 永久结束逻辑运行。 |
| **保存** | `S` | 将可编辑脚本发布为已保存的项目或用户定义。内置、带编号和恢复的运行无法保存。 |

按 `Esc` 可关闭仪表盘。

### 超出 agent 预算后恢复

处于**预算受限**状态的运行无法从仪表盘恢复。请模型恢复该运行；模型必须调用 `workflow` 工具，并传入 `resume_from_run_id` 以及高于运行当前绝对预算的 `agent_budget`。配置的最大值仍然适用。

## 恢复与保留

进程重启后，先前活跃的运行会恢复为可检查的终态**已中断**行。它们无法恢复或保存，因为不支持跨进程恢复。

运行历史有界。保留策略可能会移除较旧的终态运行和成员结果。在仪表盘中，**日志**会报告有多少较早的行已从可检索窗口中移除，**产物**会报告保留名册中省略了多少 scratch 文件名。这些提示会把保留数据丢失与运行从未产生数据区分开。

# @deepseek-ai/dsh-client-ui-workflows

[English](README.md) | 中文

`dsh-client-ui-workflows` 负责 Web 工作流运行面板。它把 `/workflows` 注册成仅客户端斜杠操作并渲染全屏浮层；打开面板不会执行 Host 命令，因此不会在聊天中追加 `workflows · Completed` 命令行。它还会为空的 `/workflow` 提供按会话查询的已保存定义选择器；`/workflow ` 和带参数的调用仍然是 Host `leadingInput` 命令。

## 面板

桌面浮层使用三个独立滚动的窗格：实时/历史运行导航、所选运行的阶段与代理名册，以及展示代理结果、日志、最终结果和 scratch 产物的检查器。中等布局保留运行导航和一个下钻窗格。窄屏布局明确地从运行切换到执行再到检查器，并提供返回控件、焦点转移和限制在视口内的滚动。运行输出控件无需代理行即可打开日志、结果或产物，因此零代理工作流也能完整检查。

运行行和成员行只含有界摘要。无 React 的 `WorkflowRunsController` 加载首个保留页并接收带修订号的变更；所选运行详情、成员分页、单个成员结果、日志、最终结果和 scratch 产物按需加载。集合修订只重新获取发生变化的集合，选择变化会中止过期读取，有界分页不会让旧响应覆盖较新的选择。

日志页会报告已被驱逐的更早行数，产物页会报告已省略的名称数，即使已没有保留行也会显示。面板不会把保留缺失误述为工作流从未写日志或 scratch 文件。

每个成员行都可选择。检查器区分仍在等待的结果、完整 JSON 值、Markdown 文本、JSON `null`、有界预览、未产生的结果、已被保留策略驱逐的值，以及可重试的请求失败。子会话导航会先通过 Session 目录解析完全匹配的直接子会话；存在结果并不表示一定能打开会话记录。

暂停、恢复、停止与保存完全从运行的 `allowedActions` 派生。按钮以及 `p`、`r`、`x`、`s` 快捷键使用同一个可用性检查，包括预算耗尽后的恢复拒绝。模态框会接管焦点、约束 Tab 导航、在整个打开期间处理 Escape、把底层 shell 设为 inert，并在关闭时恢复原焦点；只有文本输入后代拥有按键时，操作快捷键才不会触发。

## 样式

面板只使用 CSS Modules 和 `--dsw-alias-*` token。DeepSeek base 与 layer 表面在亮色和暗色主题下都保持对比度；状态始终同时用文字和颜色表达。焦点环、减少动态效果、44 像素移动端触控目标，以及 320 像素宽度下的溢出防护都属于组件约定。

## 模型体验

无，因为本包只为人类展示有界工作流运行状态，不增加 prompt、工具 schema、请求内容或模型可见结果。

#### KV Cache effect

无。

## 已知限制与延期工作

- 进程重启后，面板会从保留的运行清单恢复历史记录，而关闭时仍处于活动状态的运行会恢复为已中断。实时执行句柄、日志以及恢复权限仍只属于当前进程，因此不支持跨进程恢复工作流。
